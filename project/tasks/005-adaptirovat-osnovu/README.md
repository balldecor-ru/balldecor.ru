## Следующий шаг: SSR fallback для MODX

Сохранена файловая маршрутизация `flatRoutes()`: явно заданные маршруты, включая `_index.tsx`, имеют приоритет. Только `$.tsx` ищет старый документ по URI. Главная продолжает показывать существующий `MainPageCustom`, без обращения к MODX через fallback.

Удалён устаревший список prerender HAIH; сборка больше не обращается к отсутствующему `/solutions`. Страницы сейчас рендерятся при запросе. Исправлен импорт серверной production-сборки через абсолютный файловый URL.

Проверены `npm run types`, `npm run lint`, `npm run build`. Добавлен `tests/resource-routing.test.ts`: приоритет главной, SSR-название и кэш, query-параметры и percent-encoding, SPA-запрос `.data`, 404 и чтение восстановленного кэша без сети. В браузере проверены открытие `/services.html`, переход на главную и возврат назад с обновлением названия; ошибок гидратации в консоли не обнаружено.

Это заменяет прежнюю запись о блокере сборки. Общая адаптация сайта и проверка production-пути через Traefik/Varnish остаются открытыми.

Первые пять тестов, до расширения проверками публикации и SEO, также прошли против Node.js production-сборки на `http://localhost:3109` (`TEST_URL=http://localhost:3109 node --import tsx --test tests/resource-routing.test.ts`). Прокси и Varnish в эту проверку не входили.

После добавления фильтров публикации и SEO повторно успешно выполнены `npm run types`, `npm run lint`, `npm run build` и 17 тестов доступности/маршрутизации на dev-приложении. Состав и ограничения описаны в задаче 006. Задача 005 остаётся в работе.
