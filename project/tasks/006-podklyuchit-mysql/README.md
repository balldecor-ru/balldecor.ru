## Текущий контракт

| Запрос или поле | Поведение |
| --- | --- |
| `oldResources(where: OldResourceWhereInput, take, skip)` | Список с общим фильтром, сортировкой по ID и пагинацией. `take`: 0–100, по умолчанию 20; `skip`: от 0. |
| `oldResourcesCount(where: OldResourceWhereInput)` | Количество ресурсов с тем же фильтром, что у списка. |
| `oldResource(where: OldResourceWhereUniqueInput!)` | Обязательный `where`, внутри нужен `id` или `uri`; дополнительно доступен `context_key`. Условия объединяются через AND, отсутствие записи возвращает `null`. |
| `OldResource.TVs: [OldTemplateValue]` | Все сохранённые значения ресурса из `modx_site_tmplvar_contentvalues`, с именами TV из `modx_site_tmplvars`. |

В `oldResource` сначала создаётся query, затем проверяется наличие `id` или `uri`. При отсутствии обоих выбрасывается `BAD_USER_INPUT` до выполнения SQL. Отсутствующий или `null`-аргумент `where` отклоняется схемой GraphQL.

`TVs` загружается только при запросе поля. В списках без `TVs` запросов к таблицам TV нет. N+1 принят владельцем для этого шага: TV планируется запрашивать при получении конкретного документа. DataLoader не добавлялся.

## Следующий шаг: чтение документа в fallback и передача Apollo-кэша

`app/pages/OldResource/load.server.ts` выполняет существующий запрос `oldResource` через Apollo к локальному `/api`. Каждый серверный запрос получает отдельный клиент. URI берётся из параметра `*` React Router: он не содержит query и служебного суффикса `.data` клиентской навигации. Контекст — `web`. Явные маршруты приложения не участвуют в этом поиске.

Загрузчик передаёт `initialApolloState` через штатную сериализацию React Router. `AppProviders` собирает состояния активных маршрутов и восстанавливает Apollo до рендера дочерней страницы. При SPA-переходах поля ROOT_QUERY предыдущих страниц сохраняются. Компонент читает `pagetitle` через существующий `useOldResourceQuery`; название уже присутствует в исходном HTML. Отсутствующая запись возвращает HTTP 404, сбой API не маскируется под отсутствие документа. Для fallback установлен `Cache-Control: no-store` до согласования политики HTTP-кэширования.

Проверка: `node --import tsx --test tests/resource-routing.test.ts` против запущенного локального приложения; для другого адреса задать `TEST_URL`. Тест использует существующий документ `services.html` (ID 4) локальной базы. Проверки схемы/резолверов этим шагом не изменялись.

Границы шага сохранены: выводится только название, полное оформление, ACL, классы ресурсов, исторические редиректы и TV остаются отдельными этапами. Текущий lookup использует существующую семантику резолвера и не считается готовым публичным контрактом доступа. Трудозатраты владельцем не предоставлены.

## Проверки публикации и SEO fallback

По замечанию владельца добавлены регрессионные проверки и исправления:

- `published != 1` или `deleted != 0` → 404 до передачи loaderData/Apollo-кэша браузеру. Проверены реальный баннер №1179 (`banner-1.html`, описание «Игнат С. Топ-менеджер») и удалённый документ №120; unit-проверка отдельно покрывает удалённый, но опубликованный ресурс.
- `hidemenu` означает скрытие из меню, не запрет прямого доступа и не `noindex`. В локальной базе у «Услуг» №4 `hidemenu=1`; страница продолжает открываться. Построение меню из MODX в этот шаг не входит.
- Для fallback принята политика `searchable=1` → `index, follow`, иначе `noindex, follow`. Это явное правило новой версии: само поле MODX описывает доступность поиска и автоматически HTML robots не создаёт.
- Добавлены description из одноимённого поля ресурса, canonical и Open Graph (`type`, `site_name`, `title`, `description`, `url`). Canonical строится на `https://balldecor.ru` из сохранённого URI, без параметров и без использования входящего Host. Для 404/500 — `noindex, follow`, без canonical.
- Проверки через HTTP включают исходный HTML и `.data`, отсутствие названия/описания/нормализованной записи закрытого документа. Проверены независимые комбинации hidemenu/searchable, кириллица и завершающий слеш canonical.

Команда: `node --import tsx --test tests/resource-visibility.test.ts tests/resource-routing.test.ts`. Все 17 тестов прошли против локального dev-приложения; `npm run types`, полный `npm run lint` и `npm run build` также успешны. Новые HTTP-проверки сначала воспроизвели исходные ошибки.

Ограничения: фильтр добавлен в SSR fallback; существующие универсальные GraphQL-резолверы чтения базы не изменены и всё ещё требуют отдельного контракта доступа. ACL, сроки публикации, обработка modWebLink и TV metaTitle/metaDescription не реализованы этим шагом. Предыдущая запись об отсутствии фильтров публикации в fallback больше не актуальна.
