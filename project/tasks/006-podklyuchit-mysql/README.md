## Текущий контракт

| Запрос или поле | Поведение |
| --- | --- |
| `oldResources(where: OldResourceWhereInput, take, skip)` | Список с общим фильтром, сортировкой по ID и пагинацией. `take`: 0–100, по умолчанию 20; `skip`: от 0. |
| `oldResourcesCount(where: OldResourceWhereInput)` | Количество ресурсов с тем же фильтром, что у списка. |
| `oldResource(where: OldResourceWhereUniqueInput!)` | Обязательный `where`, внутри нужен `id` или `uri`; дополнительно доступен `context_key`. Условия объединяются через AND, отсутствие записи возвращает `null`. |
| `OldResource.TVs: [OldTemplateValue]` | Все сохранённые значения ресурса из `modx_site_tmplvar_contentvalues`, с именами TV из `modx_site_tmplvars`. |

В `oldResource` сначала создаётся query, затем проверяется наличие `id` или `uri`. При отсутствии обоих выбрасывается `BAD_USER_INPUT` до выполнения SQL. Отсутствующий или `null`-аргумент `where` отклоняется схемой GraphQL.

`TVs` загружается только при запросе поля. В списках без `TVs` запросов к таблицам TV нет. N+1 принят владельцем для этого шага: TV планируется запрашивать при получении конкретного документа. DataLoader не добавлялся.

## Проверено

Проверки выполнены после последнего изменения входных аргументов, до записи этого ворклога:

```sh
npm run lint
npm run types
node --import tsx --test tests/old-resources.test.ts
```

Все три проверки прошли. Интеграционный тест обращался через GraphQL-схему к реальной локальной MySQL и подтвердил:

- количество соответствует прямой SQL-выборке;
- список отсортирован, фильтры списка и количества согласованы;
- получение по ID и URI работает;
- сохранённые TV соответствуют строкам БД;
- список без `TVs` не обращается к таблицам TV;
- отсутствующий ресурс возвращает `null`, `take: 0` — пустой список;
- отсутствие обязательного `where`, пустой фильтр, оба идентификатора `null`, один `context_key` и неверная пагинация отклоняются без SQL.

Это проверка схемы и резолверов, не отдельная проверка HTTP `/api` или Docker-сети. Полная сборка сайта блокируется старым prerender `/solutions`; подробности в задаче 005.
