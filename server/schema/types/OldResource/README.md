# Чтение старых ресурсов

Knex использует `mysql2` и серверную переменную `MYSQL_URL`, как в проекте-примере. Локальный запуск через `npm run dev` читает корневой `.env` (исключён из Git):

```dotenv
MYSQL_URL=mysql://USER:PASSWORD@127.0.0.1:3306/balldecor
```

Специальные символы логина и пароля нужно кодировать для URL. Для Docker адрес должен быть доступен из контейнера; переменную передаём через `docker/.env`, указанный в Compose. Локальный `127.0.0.1` указывает на опубликованный порт старой базы при запуске Node.js на хосте.

Запросы `/api`:

```graphql
query {
  oldResourcesCount(where: { deleted: 0 })
  oldResources(where: { parent: 0 }, take: 20, skip: 0) {
    id
    pagetitle
    uri
    template
  }
  oldResource(where: { id: 1 }) {
    id
    pagetitle
    content
    TVs {
      id
      tmplvarid
      contentid
      name
      value
    }
  }
}
```

`oldResource` принимает обязательный `where: OldResourceWhereUniqueInput!` с `id` или `uri`; внутри `where` можно дополнительно передать `context_key`. Пустой `where` или только `context_key` вызывают `BAD_USER_INPUT` до выполнения SQL. Переданные условия объединяются через AND. Отсутствующая запись возвращает `null`. Список сортируется по ID, `take` — 0–100 (по умолчанию 20), `skip` — от 0. Фильтры `oldResourcesCount` и `oldResources` используют необязательный `where: OldResourceWhereInput`. Флаги и даты сохраняют числовое представление MODX; `price` возвращается строкой без потери точности DECIMAL, `properties` — исходной строкой.

`TVs` читает все сохранённые значения конкретного ресурса, включая пустые строки. Имя TV присоединяется из `modx_site_tmplvars`; отсутствие определения не удаляет значение. Значения по умолчанию из определения, наследование, `@BINDING` и обработчики MODX не вычисляются. Без поля `TVs` SQL к таблице значений не выполняется. При запросе поля у нескольких ресурсов выполняется отдельный запрос на каждый ресурс, согласно принятому для этого шага решению.

Это доступ к исходным данным для локального этапа миграции: фильтры публикации, удаления и ACL автоматически не применяются. Перед внешней публикацией API необходимо реализовать контракт доступа из задачи 003. Мутаций и миграций базы нет.

Интеграционная проверка на подключённой локальной копии (только SELECT):

```sh
node --import tsx --test tests/old-resources.test.ts
```

## Структура

Модели `OldResource` и `OldTemplateValue` расположены в отдельных каталогах. `index.ts` описывает поля модели, `interfaces.ts` — строки базы, `types.ts` — ссылку Pothos, `inputs.ts` — входные фильтры. В `OldResource/resolvers/` каждый запрос и поле `TVs` имеют свой файл; общий SQL-фильтр находится в `helpers/queryOldResources.ts`.
