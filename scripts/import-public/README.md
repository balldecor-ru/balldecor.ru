# Импорт в SQLite и HAST

Актуальная реализация сохраняет страницы в `KBConcept`, адреса — в `KBConcept.uri`.
Импортер не читает и не заполняет `SiteRoute`.
Отдельные TSX-файлы для документов больше не генерируются. MySQL используется
только импортером; рабочие страницы читают SQLite через GraphQL.

- `hast`: JSON-дерево очищенного контента, включая исходные комментарии.
- `contentMode`: `hast` для импорта, `default` по умолчанию для остальных концептов.
- `type`: `old:page:${template}:${class_key}`; ID концепта: `old:page:${id}`.
- `tv`: массив всех сохранённых TV документа (`id`, `tmplvarid`, `contentid`,
  `value`, `name`), включая пустые значения и значения без определения TV.
  Как и существующий API, не вычисляет defaults, наследование и MODX bindings.
- `searchable`: исходный признак индексации. `false` запрещает индексацию и
  включение в sitemap; HTML noindex дополнительно сохраняется в `data.noindex`.
- `visibility`: `unpublished` для удалённых, закрытых, неопубликованных,
  находящихся вне срока публикации и неподдерживаемых ресурсов; иначе
  `hidden` при `hidemenu = 1`, `public` для остальных.
- Исходные признаки, HTTP-статус, редирект и параметры OG-изображения — в `data`.
  Исходный parent сохраняется всегда, `parentId` связывается с импортированным
  родителем после завершения выборки.
- Изображения сохраняются в `uploads/old` с исходными именами и вложенностью.
  Например, `/assets/images/example/photo.jpg` хранится в
  `uploads/old/assets/images/example/photo.jpg` и доступен по прежнему URL.
  Папки создаются рекурсивно. Статика подключена в `server/index.ts` до ресайзера.

По умолчанию `--force false` пропускает существующие ресурсы без скачивания
и изменения записей. `--force true` перезаписывает выбранные ресурсы и изображения.
Каждая страница сохраняется одной транзакцией. Ошибка не откатывает уже импортированные страницы.
Продолжение поддерживает `id.gte`. Закрытые документы сохраняются как unpublished
без запроса публичного HTML; при обновлении существующей записи её HAST сохраняется.

```sh
npm run import:public -- --where '{"id":1}' --limit 1
npm run import:public -- --limit 4643
npm run import:public -- --where '{"id":{"gte":5518}}' --limit 4643
```

Для выбора нескольких ресурсов используйте `id.in` с массивом целых чисел:

```sh
npm run import:public -- --where '{"id":{"in": [1,22,5408]}}' --limit 10 --flash true
```

`id.in` можно сочетать с `id.not` и `id.gte`. Пустой массив не выбирает ресурсы.

`--flash false` (по умолчанию) сохраняет имеющиеся записи.
`--flash true` перед импортом транзакционно очищает только `KBConceptFile`,
`KBConcept`. Связанные записи удаляются по существующим правилам внешних ключей
SQLite. Пользователи, файлы и изображения на диске не удаляются. Оба параметра принимают только `true` или `false`.

Очистка таблиц и импорт только главной:

```sh
npm run import:public -- --where '{"id":1}' --limit 1 --flash true --force true
```

`--where` и `--limit` необязательны и независимы. Базовая выборка всегда содержит
условия `published=1`, `deleted=0`, `privateweb=0`, `context_key=web` и `id != 23`
(XML-карта сайта). Входящий `--where` добавляется через AND и не заменяет эти
условия, в том числе при передаче `id.not` или `id.gte`. Противоречащий базовой
выборке фильтр не выбирает ресурсы и завершает запуск до очистки `--flash`.
Без `where` выбираются все ресурсы базовой выборки, без `limit` количество
не ограничивается. Проверки фильтра и положительного целого лимита сохраняются.

```sh
npm run import:public -- --flash true
```

SQLite задаётся стандартным `DATABASE_FILENAME`, источник — `MYSQL_URL`.
Необязательный `--author-id` выбирает существующего пользователя; без него создаётся
заблокированный технический автор `old:importer`, без пароля и прав администратора.

Фронтенд рендерит HAST через `hast-util-to-jsx-runtime`; внутренние ссылки используют
React Router Link. Главная и остальные импортированные URL обслуживаются общим
механизмом концептов. Редиректы, noindex и исходные HTTP 4xx сохраняются.

## История: состояние после изменения хранения изображений

Выполнен импорт с `--flash true --force true --where '{"id":1}' --limit 1`.
В `KBConcept` и `SiteRoute` осталась только главная, `KBConceptFile` пустая;
количество записей в остальных 12 таблицах не изменилось.

Проверены пропуск существующего ресурса без изменения записи и файлов,
перезапись через `force=true`, HTTP 200 главной и всех 46 изображений.
Байты изображений в `uploads/old` и HTTP-ответах свежего экземпляра сервера
совпали с источником. Изображения доступны по исходным путям.

## История: результат первого перехода на SQLite

Перенесены 4642 ресурса: 4574 страницы и 68 редиректов. Сверены с MySQL
адреса, типы, исходные признаки, связи родителей и 13178 сохранённых значений TV.
Проверено наличие всех 15698 файлов изображений, на которые ссылаются HAST и SEO.
В HAST сохранены 2444 комментария исходных страниц.

Прошли генерация GraphQL, `npm run types`, `npm run lint`, 10 целевых тестов
и `npm run build`. Production-сервис проверен с пустым `MYSQL_URL`: HTTP 200,
401, 404, редирект 302 и noindex; браузерный переход выполняется без перезагрузки,
ошибок гидратации в проверенном сценарии нет. Действующий домен не переключался.

# Импорт публичного контента MODX

Первый этап переносит только главную страницу. Оформление, анимации, калькулятор,
карусель и другие интерактивные механизмы старого сайта не реализуются.

Запуск из корня проекта при работающем старом сайте и настроенном `MYSQL_URL`:

```sh
npm run import:public -- --where '{"id":1}' --limit 1
```

`--where` — JSON-объект равенств технических полей ресурса; `--limit` — обязательное
положительное целое число. Выборка сортируется по ID. SQL-выражения не принимаются.
Для исключения одного ID поддерживается `"id":{"not":23}`. Полный запуск без XML-карты сайта:

```sh
npm run import:public -- --where '{"published":1,"deleted":0,"privateweb":0,"context_key":"web","id":{"not":23}}' --limit 4643
```

Доступны поля из `ImportedResource`: `id`, `uri`, `published`, `searchable`, `hidemenu`, `deleted`,
`privateweb`, `parent`, `template`, `context_key`, `class_key`, `pub_date`, `unpub_date`.

Дополнительные параметры:

- `--base-url http://localhost:8080` — адрес публичного старого сайта.
- `--selector 'body > main.container'` — явный CSS-селектор контентных блоков
  для другого шаблона; вложенные друг в друга выбранные блоки запрещены.

Из MySQL читаются только перечисленные технические поля и настройка `site_start`.
Исключение — `modWebLink`: назначение читается из `content`, статус из
`properties.core.responseCode` (по умолчанию 301, как в MODX). HTTP-запросов для
веблинков нет. Числовое назначение разрешается в URI ресурса, `[[++site_url]]` —
в корень сайта; внутренние адреса становятся локальными. Генерируется маршрут
с redirect-loader и типизированными данными. При `searchable !== 1` ответ содержит
`X-Robots-Tag: noindex`.
Контент, заголовок, description, robots и OG-изображение берутся из публичного HTML.
Блоки выбираются по исходному `template` через таблицу в `templates.ts`:

- `0`: содержимое `body`, без самого тега `body`; при отсутствии `title` используется URI;
- `1`: `body > section.zapravka`, `body > header.container`, `body > main.container`;
- `8`, `11`: `body > header.container` и `body > main`;
- `34`: `body > main.container`;
- `2`, `4`, `5`, `7`, `9`, `10`, `14`, `15`, `17`, `18`, `27`, `28`, `29`, `30`, `31`, `33`,
  `36`: `body > main`.

Каждый обязательный блок должен встретиться ровно один раз. Блоки возвращаются
в порядке исходного DOM. Неизвестный шаблон вызывает ошибку с ID ресурса,
ID шаблона и URI; общего запасного селектора нет. `--selector` явно переопределяет
правило и допускает несколько блоков. `site_start` определяет только маршрут `/`,
а не способ выделения контента.

Правила проверены на представителях перечисленных шаблонов. Для шаблонов `28` и `33`
на старом сайте исправлен вывод результатов `where()` и `select()` в Smarty:
присваивание переменной вместо вывода объекта запроса. Обе контрольные страницы
после исправления возвращают HTTP 200 и контент без PHP-ошибок.
Шаблон `35` на проверенном URL возвращает HTTP 401. Шаблон `0` поддерживается для
HTML-документов и `text/plain`: обычный текст помещается в JSX как строка без
HTML-разбора, заголовком служит URI. XML sitemap (`id: 23`) исключён фильтром запуска.

Исходный `searchable` сохраняется в `sourceResource`. Если `searchable !== 1`,
SEO получает `noindex: true`. При `searchable === 1` сохраняется исходный запрет
индексации из публичного HTML, если он есть.

Результат для каждого ресурса находится в `app/Custom/pages/Imported/Resource<ID>/`:

- `index.tsx` — отдельный React-компонент с JSX-контентом, без HTML-строки и без
  обращения к старому сайту при отображении;
- `data.ts` — типизированные исходные признаки `sourceResource` и SEO;
- `assets/` и `assets.ts` — скачанные изображения и их статические импорты;
- `route.tsx` — модуль маршрута с SEO.

`routes.json` хранит пути импортированных страниц. `app/routes.ts` добавляет
неглавные маршруты к существующим. Главная подключена через существующие
`MainPage` и `_index.tsx`. Исходный URI главной `index.html` сохраняется в данных,
а публичный маршрут `/` определяется по `site_start`.

Относительные внутренние ссылки приводятся к абсолютным путям сайта. Ссылки на
старый домен также становятся локальными; query и hash сохраняются. Обычные
внутренние ссылки используют React Router `Link`. Пути ещё не перенесённых страниц
сохраняются, но сами эти страницы текущий запуск не создаёт. `hidemenu` означает
скрытие из меню и не запрещает импорт опубликованной страницы.

Импорт прекращается при закрытом/удалённом/неопубликованном ресурсе, неподходящем
контексте или классе, серверном HTTP 5xx, сетевом сбое, неожиданном редиректе,
отсутствующем блоке контента, object и embed внутри выбранного блока.
Изображения с отсутствующим, пустым или состоящим из пробелов `src` не скачиваются:
импортер выводит предупреждение с ID, шаблоном и URI страницы, убирает пустой `src`
и сохраняет сам элемент, подпись и окружающую ссылку. Импорт страницы продолжается.
Изображения с любым итоговым HTTP-статусом, отличным от 200, удаляются из контента
с предупреждением в логе; окружающие ссылки сохраняются. Такое OG-изображение
не включается в SEO. Недоступные изображения при сетевых ошибках, таймаутах и
ошибках сертификатов также удаляются с причиной в логе; проверка TLS не отключается.
`srcset` пока требует отдельного правила переноса.
Неудачный запуск может оставить уже скачанные изображения и подготовленные файлы;
реестр уже успешно обработанных маршрутов сохраняется и при остановке на ошибке.

Теги `<script>`, `<style>` и `<iframe>`, атрибуты `style`, обработчики `on*` и исполняемые
адреса `javascript:` удаляются. Исходные классы, `data-*` и остальные комментарии сохраняются в компоненте;
дополнительные стили и старые JS/CSS-бандлы не добавляются. Кнопка калькулятора
сохраняет `data-src`, но без старого JS она не работает. Элементы управления каруселью также остаются
разметкой. Это не обычные переходы на страницы и требует отдельной реализации.

Атрибуты `tabindex` удаляются; пустой `href` опускается. Старые якоря `<a name>`
преобразуются в `id`. Если у элемента уже есть другой `id`, исходный именованный
якорь сохраняется отдельным `span` перед элементом, чтобы оба адреса `#…` работали.

Повторный запуск обновляет сгенерированные файлы выбранных ресурсов и оставляет
другие записи реестра. Редактировать сгенерированный компонент следует после
завершения его импорта: последующий импорт перезапишет эти изменения. Файлы без
маркера импортера не перезаписываются. Старые изображения автоматически не удаляются.

Проверка первого переноса: сравнение текста, 75 ссылочных элементов (74 обычных
адреса и один `javascript:;`), 48 вхождений изображений и их байтов с публичной
главной; скачано 46 уникальных URL изображений, включая OG. Проверки `types` и `lint`
выполняются штатными npm-командами.

DOM преобразуется в JSX библиотеками `hast-util-from-dom`, `hast-util-to-estree`
и `estree-util-to-js`. Числовые атрибуты определяются справочником
`property-information`, списки координат и строковые размеры сохраняются.
Собственные преобразования связывают локальные изображения, `Link` и старый
тег `noindex`. В готовых страницах нет парсера HTML или `dangerouslySetInnerHTML`.

Для HTTP 4xx (включая 401 и 404) сохраняется HTML публичного ответа и создаётся маршрут с тем же
HTTP-статусом через React Router loader. Это статический ответ для анонимного
посетителя, без реализации авторизации. Статус хранится в `data.ts` как `httpStatus`.

HTTP-редиректы публичных документов также сохраняются как редиректы с исходным
статусом и локализованным адресом назначения. Для продолжения прерванного импорта
доступен фильтр `"id":{"not":23,"gte":5518}`: ранее созданные маршруты остаются
в реестре. `gte` включает указанный ID.
